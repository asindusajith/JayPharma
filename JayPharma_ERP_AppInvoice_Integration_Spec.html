📌 Executive Overview for Main System Engineers

The JayPharma Mobile Field Collection Application is used by field medical representatives and collection agents to collect cash/cheque payments from pharmacies and hospital accounts. When an agent confirms a collection on their mobile device, the JayPharma backend service immediately writes the settlement data to the Main ERP SQL Server Database.

Critical Safety Architecture: The mobile application NEVER writes to, alters, or locks the dbo.Invoice table directly. Instead, all field collections are inserted as pending audit records into dbo.AppInvoice and dbo.DPay. This guarantees 100% data integrity, prevents concurrency collisions with head-office ERP billing users, and provides complete traceability with receipt numbers, collector IDs, and GPS stamps.

4. Business Logic & Allocation Scenarios

Scenario A: Exact or Partial Single Invoice

Agent collects Rs. 10,000 for Invoice #101 (Val: Rs. 25,000).
• InvNo = 101, InVal = 25000, SetAmt = 10000
• SettleType = 'Part Settled', DOther1 = 15000
• Other1 = 'MR-001', DOther2 = 10000

Scenario B: Multi-Invoice Split Payment

Agent collects Rs. 30,000 to settle Invoice #101 (Rs. 10,000) and Invoice #102 (Rs. 20,000).
• Row 1: InvNo = 101, SetAmt = 10000, Other1 = 'MR-002'
• Row 2: InvNo = 102, SetAmt = 20000, Other1 = 'MR-002'
Both rows share the exact same Receipt No (Other1).

Scenario C: Pure Advance Payment (No Invoices)

Customer pays Rs. 50,000 on account before billing.
• InvNo = 0, InVal = 0, SetAmt = 50000
• SettleType = 'Advance', DOther1 = 0, DOther2 = 50000
• DPay entry records InvNo = 0 with full amount.

Scenario D: Overpayment with Excess Balance

Customer has Rs. 10,000 invoice, but hands over Rs. 15,000.
• Row 1: InvNo = 101, SetAmt = 10000, SettleType = 'Settled'
• Row 2: InvNo = 0, SetAmt = 5000, SettleType = 'Advance'
Excess is automatically preserved as an Advance row!

5. How ERP Computes Effective Realtime Balance (Query Example)

-- Recommended SQL View / Query to compute Real-Time Customer Outstanding: SELECT i.InvNo, i.CCode, i.CName, i.Date AS InvoiceDate, i.InVal AS OriginalAmount, (ISNULL(i.SetAmt, 0) + ISNULL(app.AppSettled, 0)) AS TotalSettledAmount, (i.InVal - (ISNULL(i.SetAmt, 0) + ISNULL(app.AppSettled, 0))) AS EffectiveOutstandingBalance, CASE WHEN (i.InVal - (ISNULL(i.SetAmt, 0) + ISNULL(app.AppSettled, 0))) <= 0.01 THEN 'Settled' WHEN (ISNULL(i.SetAmt, 0) + ISNULL(app.AppSettled, 0)) > 0 THEN 'Part Settled' ELSE ISNULL(i.SettleType, 'Pending') END AS CurrentStatus FROM dbo.Invoice i LEFT JOIN ( SELECT InvNo, SUM(ISNULL(SetAmt, 0)) AS AppSettled FROM dbo.AppInvoice WHERE InvNo > 0 GROUP BY InvNo ) app ON i.InvNo = app.InvNo WHERE (i.InVal - (ISNULL(i.SetAmt, 0) + ISNULL(app.AppSettled, 0))) > 0.01;
